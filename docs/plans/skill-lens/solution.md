# Skill Lens 方案层

## 面向谁

内部工具 / 自用：面向经常让 Codex 执行复杂工作流、需要知道“它到底加载了什么规则”的用户。

## 痛点

Codex 会先发现 Skill 元数据，再按任务需要读取完整 `SKILL.md`。现在这些状态散落在文件系统和执行过程里，用户无法在一个稳定入口中确认可用 Skill、查看原文或理解最近读取情况。

## 主路径

1. 用户从 Codex 侧边栏打开 Skill Lens，系统扫描允许的本地 Skill 目录。
2. 面板直接展示当前 Session 检测到读取的 Skill，不要求用户输入提示词或发起查询。
3. 用户点击一个 Skill，系统展示它的完整 `SKILL.md` 原文、路径和修改时间。
4. 用户需要检查机器上的完整目录时，主动切换到“全部 Skill”，再使用面板内搜索或来源筛选。
5. Codex 经本地工具读取 `SKILL.md` 后，Hook 与 Session 日志形成新的活动版本。
6. 面板可见时自动核对活动版本；新读取出现后自动更新列表，不要求用户手动刷新。
7. 用户可以在“跟随当前”和“固定此 Session”之间切换：全局入口默认跟随，检查特定上下文时可暂时固定。

## 不做什么

- 不修改、启用或停用任何 Skill。
- 不声称 Hook 推断等于官方 `SkillActivated` 事件。
- 不读取密钥、聊天正文或 Skill 目录之外的文件正文。
- 首版不提供 Skill 编辑器和跨设备同步。
- 不通过聊天消息、`@mention` 或模型调用来打开或查询 Skill Lens。
- 不承诺插件能强制 Codex 永久展开侧面板；入口与面板生命周期仍由宿主控制。
