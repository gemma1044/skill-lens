# Skill Lens 实现层

## 实施方案

| 实现点 | 现状 | 目标状态 | 状态 |
| --- | --- | --- | --- |
| Codex 入口 | 已有 global + thread entrypoint，但使用说明容易让用户在聊天中发起任务 | 保持 app-only entrypoint；用户点击入口后直接显示，不经过聊天查询 | 本期修正 |
| Skill 数据 | 分散在本地 `SKILL.md` | 只读扫描、解析元数据并按来源分类 | 本期新增 |
| 活动数据 | 无官方激活事件 | `PostToolUse` Hook 记录成功工具调用中出现的 `SKILL.md` 路径 | 本期新增 |
| 正文查看 | 需要手动开文件 | 点击列表读取扫描白名单内的原文 | 本期新增 |
| 自动更新 | 只有首次打开与手动刷新会重扫 | 可见时轮询轻量活动版本；变化后才重扫完整目录 | v0.1.4 新增 |
| Session 归属 | 打开时读取一次宿主 Session | 默认跟随当前 Session，也可固定初始 Session；焦点或宿主上下文变化时立即核对 | v0.1.4 新增 |
| 其他 Skill | 保持原状 | 不写入、不重排、不复制 | 保持不变 |

## 兜底与边界

- 失败 / 空态：目录不可读时跳过；没有结果时显示可操作空态。
- 部分成功：某个文件解析失败不阻断其他 Skill。
- 结果不确定：状态文案固定为“检测到读取”，并持续展示口径说明。
- 重复触发：活动日志允许重复写入，展示时按路径取最近一次。
- 回退：停用或卸载插件即可；Hook 只写插件自己的 `PLUGIN_DATA`。
- 权限：正文读取严格限制在本轮扫描结果内，任意路径参数会被拒绝。
- 脏数据：无 frontmatter 时以文件夹名兜底，并标出缺少 description。
- 超时 / 暂时失败：保留上一份可用快照，状态改为“自动更新暂时中断”，下一轮继续安全重试。
- 并发：状态检查使用单飞锁，避免定时器、焦点事件和宿主事件同时发起重复扫描。

## 验收要点

1. Sidebar App 可打开并列出真实本地 Skill。
2. 点击条目显示与磁盘完全一致的 `SKILL.md`。
3. Hook 写入一条模拟读取后，对应 Skill 显示活动状态。
4. 当前 Session 默认页无搜索和筛选；全部 Skill 目录中的搜索、筛选、移动端布局和键盘焦点均可用。
5. 新读取发生后无需手动点击即可出现；切换为固定模式后不会被后续 Session 上下文替换。
